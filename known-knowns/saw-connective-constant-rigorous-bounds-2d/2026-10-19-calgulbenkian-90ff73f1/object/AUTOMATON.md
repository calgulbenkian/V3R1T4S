# Definition of the automaton and of the state file

All of this is also implemented, from this text alone, in verify-it-yourself/check_saw482.py. The object holds only the test vector; the states and transitions are regenerated by the checker.

## Lattice
Vertices: integer points (x, y) with (x mod 3, y mod 3) one of (1,0) type E, (2,0) type W, (0,1) type N, (0,2) type S. Neighbours (offsets), in this fixed order:
- E: (-1,+1), (-1,-1), (+1,0)
- N: (+1,-1), (-1,-1), (0,+1)
- W: (+1,+1), (+1,-1), (-1,0)
- S: (+1,+1), (-1,+1), (0,-1)
This is the 4.8^2 lattice (every vertex has degree 3). dist is graph distance.

## Automorphisms used
sigma = translation by (3a, 3b) composed with one of 8 symmetries g_s about the origin: for s = 0..7, first sx = -x if bit 0 of s else x; sy = -y if bit 1 of s else y; then (sy, sx) if bit 2 else (sx, sy).

## Walks and states
A walk is a list of distinct vertices, consecutive ones adjacent, oldest first, head last. Its canonical key: let (ax, ay) be the head, rx = ax mod 3, ry = ay mod 3, tx = ax - (-1 if rx == 2 else rx), ty = likewise. Translate all points by (-tx, -ty), apply each of the 8 symmetries, and keep the symmetry whose coordinate sequence (x, then y, of the head, then of the previous point, and so on back to the oldest) is lexicographically smallest. The head of a canonical walk is therefore always (-1, 0). A state is a canonical walk.

Loop length k (K in the checker; K = 32 for this claim). prune(walk): drop oldest vertices one at a time (start = 0, 1, ...) while start < len - 2 and (len - 1 - start) + dist(walk[start], head) > k; the result walk[start:] is canonicalised.

## Seeds
The canonical forms of the walks [(1,0),(0,1)] (square edge) and [(1,0),(2,0)] (octagon edge). Index 0 is the square seed, index 1 the octagon seed.

## Transitions and the canonical state order (regenerated by the checker)
The state set is the smallest set containing the two seeds and closed under rules 1 and 2 below. It is listed in this order: the seeds first; then the states are expanded in index order; for each state, for each neighbour A of its head in the fixed neighbour order, with A not in the state's vertex set V, let ext = walk + [A]; the new states met while processing that transition are appended to the list, in the order they are met, if they are not yet in the list (rule 1's c0 first, then the rule-2 shortcuts in the order described, depth-first: a shortcut's state is appended before the recursion into it). The test vector (see below) is given in this order.
Candidate targets of the transition:
1. c0 = prune(ext).
2. If (len(ext) - 1) + dist(ext[0], A) > k: chord shortcuts. For a from min_a (initially 0) up to len(walk) - 4 and, for each b with a + 2 <= b <= len(walk) - 2 in increasing order, such that walk[a] and walk[b] are adjacent: the shortcut sx = walk[0..a] + walk[b..end] gives the state prune(sx), which is always appended to the state list if new, and is a candidate if not already one and fewer than 64 candidates exist; and if the recursion depth is below 3 and (len(sx) - 1) + dist(sx[0], head) > k, recurse on sx with depth + 1 and min_a = a. (Here walk means the walk being examined at that level, and its last vertex is the new head.)
3. Also, if (len(ext) - 1) + dist(ext[0], A) > k: for start = 0, 1, ... while start < len(ext) - 2 and (len(ext) - 1 - start) + dist(ext[start], A) > k, the canonical form of ext[start:] is a further candidate if it is ALREADY in the final state list (it never creates a state) and fewer than 32 candidates so far.
The target is the candidate with the smallest test-vector entry. Each chosen target is verified to satisfy the subset-inclusion invariant (THEOREM.md) against the target state itself, so the theorem does not depend on the exact shape of the candidate lists; the lists matter only for which bound results.

## Vector file (object/vector_part_NN.bin concatenated, in this order)
- 8 bytes: the ASCII text SAW482V2.
- then one xz (lzma) stream. Decompressed it is 6 * N bytes, N = number of states: six planes of N bytes. Plane j (j = 0..5) holds, for state index i = 0..N-1 in the canonical order above, byte j of the 48-bit big-endian unsigned integer x_i (plane 0 is the most significant byte).
The vector entries x_i are positive integers (between 10^6 and 10^13 here). The number of states is not stored; the checker regenerates the state set and requires the same count.

## Clarifications added after the panel
The reproduce skeptic, writing its own checker from the text above, found two sentences that can be read two ways. They change which bound results, not whether the bound is valid (every chosen transition is checked against the subset-inclusion invariant). This section only states the reading the checker uses; the definition above, the vector and the checker are unchanged.

1. Rule 2 (chord shortcuts) acts on the extended walk, not on the state before the move. The "walk" on which rule 2 starts is ext = walk + [A], the walk of the state with the new neighbour A appended, so its last vertex is A. The conditions "walk[a] and walk[b] are adjacent", "a + 2 <= b <= len(walk) - 2" and "a up to len(walk) - 4" are evaluated on this extended walk (len counts A). In the recursion, the walk being examined is the shortcut walk sx, whose last vertex is again A. Reading rule 2 as acting on the state before extension gives a different candidate set and fails the subset-inclusion invariant on 11,430 chosen transitions at k = 22 (the skeptic's test against the known-answer vector).
2. Rule 3 (intermediate suffixes) takes ext[start:] at every value of start that the loop visits, not ext[start + 1:]. For start = 0, 1, 2, ... in turn, while start < len(ext) - 2 and (len(ext) - 1 - start) + dist(ext[start], A) > k, the walk ext[start:] (canonicalised) is a further candidate if it is already in the final state list. The first start at which the inequality fails is where c0 = prune(ext) begins, so c0 is not repeated by rule 3. The skeptic reports that the other offset (start versus start + 1) gives identical results at k = 22 and at k = 32.
